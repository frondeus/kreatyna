# P05 — Keep accepted saves through shutdown

Tracked in beads: `vibetyna-bka` (P05) and `vibetyna-mzf` (P03). Change: "P05:
keep accepted saves through shutdown". Analysis:
[R13-ffi-problems.md, P05 and P03](../R13-ffi-problems.md).

## Open questions

None. The user answered P05/Q1–Q5 in the Inbox thread "P05" before this plan.

## Decisions

| ID | Decision |
| --- | --- |
| P05/Q1 | When you quit during a save, the app waits for the save to finish. |
| P05/Q2 | The wait has a limit of 5 seconds. After the limit, the app quits anyway. Rust reports that it cancelled pending work, and it writes a log line. |
| P05/Q3 | This change also fixes P03 (shutdown has no observable completion). Both beads close together. |
| P05/Q4 | This change covers the Mac. iOS is a follow-up bug: `vibetyna-w8q`, "iOS: ask for background time while a save is pending". |
| P05/Q5 | A dirty form that you did not save is out of scope. Follow-up: `vibetyna-3rv`, "Quit asks “Discard changes?” for a dirty form". |

## Outcome

You type “Garlic” in the new-ingredient form, press <kbd>⌘S</kbd>, and press
<kbd>⌘Q</kbd> at once. The app stays open for the few milliseconds the save
needs, then quits. On the next launch, “Garlic” is in the catalog.

If the database is locked by another program, the save cannot finish. The app
waits 5 seconds, then quits. The log has the line “Graceful shutdown timed out;
cancelling pending work”.

## Terms

| Term | Meaning |
| --- | --- |
| Accepted work | An event that `dispatch()` accepted, and every command that its update started, for example a save request to SQLite and the result that comes back. |
| Graceful shutdown | A krucyfiks runtime mode. The runtime stops accepting new events, finishes the accepted work, then stops. Its runner future completes when all work is done. |
| Cancel shutdown | A krucyfiks runtime mode. The runtime stops at once and drops pending work. `AppFfi::shutdown()` uses it today. |
| Runner | The future that `Runtime::start()` returns. `AppFfi::start()` spawns it on Tokio and keeps its `JoinHandle`. When the runner ends, the runtime has stopped. |
| `applicationShouldTerminate` | The AppKit call that asks the app delegate whether the app may quit. The answer `.terminateLater` delays the quit until the app calls `NSApp.reply(toApplicationShouldTerminate: true)`. |

## Design

No UI change. The app looks the same; quit takes up to 5 seconds longer only
while a save is still running.

## Changes by layer

### db

None. SQLite already commits each save in one transaction. A transaction that
the process interrupts does not commit.

### rust

None in `crates/kreatyna`. The widgets already work with graceful shutdown:
their `can_begin_shutdown()` and `begin_shutdown()` hooks came with S02.

### ffi (`crates/kreatyna-ffi`)

1. `AppFfi` gets an async method, `shut_down_gracefully()`. Swift awaits it.
   It returns how the shutdown ended.

   ```rust
   // sketch
   /// How long graceful shutdown waits for accepted work (P05/Q2).
   const SHUTDOWN_GRACE: Duration = Duration::from_secs(5);

   #[derive(Debug, Clone, Copy, PartialEq, Eq, uniffi::Enum)]
   pub enum ShutdownResult {
       /// All accepted work finished: every accepted save committed or failed
       /// visibly before the runtime stopped.
       Completed,
       /// Accepted work outlasted the grace period and was cancelled.
       Cancelled,
   }

   #[uniffi::export]
   impl AppFfi {
       /// Stops accepting events, finishes accepted work, and returns when
       /// the runtime has stopped. Call it once, when the app quits.
       pub async fn shut_down_gracefully(&self) -> ShutdownResult {
           self.shut_down_within(SHUTDOWN_GRACE).await
       }
   }
   ```

2. `shut_down_within(grace)` is private, so tests can use a short limit.

   ```rust
   // sketch
   async fn shut_down_within(&self, grace: Duration) -> ShutdownResult {
       self.runtime.request_shutdown(ShutdownMode::Graceful);
       // Not started: the runtime accepted no work.
       let Some(mut runner) = self.handle.lock().take() else {
           return ShutdownResult::Completed;
       };
       let runtime = self.runtime.clone();
       RUNTIME
           .spawn(async move {
               match tokio::time::timeout(grace, &mut runner).await {
                   Ok(_) => ShutdownResult::Completed,
                   Err(_) => {
                       tracing::warn!(?grace, "Graceful shutdown timed out; cancelling pending work");
                       runtime.request_shutdown(ShutdownMode::Cancel);
                       let _ = runner.await;
                       ShutdownResult::Cancelled
                   }
               }
           })
           .await
           .unwrap_or(ShutdownResult::Cancelled)
   }
   ```

   The method awaits a Tokio `JoinHandle`. That future works on any executor,
   so UniFFI's own executor can poll it. The timer runs inside the spawned
   task, on the app's Tokio runtime.

3. The Tokio runtime gets its timer: add `.enable_time()` to the builder in
   `lib.rs`, and the `time` feature to `tokio` in `Cargo.toml`.
4. `shutdown()` keeps cancel mode. `Drop` still calls it. Tests and previews
   use it, and it is correct when no work must survive.

The database worker needs no change. A save command finishes only after the
worker sends its response, and the worker sends it after the commit. So when
the runner ends, every accepted save has committed or failed. Releasing the
connection early stays P04.

### swift

1. `Shared/AppModel.swift`: add `func shutDownGracefully() async`. It awaits
   `core?.shutDownGracefully()`. Without a core it returns at once. Rust
   already logs a timeout, so Swift does not log again.
2. `KreatynaMac/MacAppDelegate.swift` (new): an `NSApplicationDelegate` that
   owns the `AppModel`.

   ```swift
   // sketch
   @MainActor
   final class MacAppDelegate: NSObject, NSApplicationDelegate {
       let model = AppModel()

       func applicationShouldTerminate(_ sender: NSApplication) -> NSApplication.TerminateReply {
           Task {
               await model.shutDownGracefully()
               sender.reply(toApplicationShouldTerminate: true)
           }
           return .terminateLater
       }
   }
   ```

3. `KreatynaMac/KreatynaMacApp.swift`: add
   `@NSApplicationDelegateAdaptor(MacAppDelegate.self) private var delegate`,
   and pass `delegate.model` to `ContentView`.
4. `KreatynaMac/ContentView.swift`: take the model as a parameter instead of
   creating it with `@State`. The delegate must own the model, because it
   needs the model at quit time.
5. iOS: no change (P05/Q4). `AppModel` is shared, so iOS compiles the new
   method but does not call it.

Differences from the plan:

1. `graceful_shutdown_keeps_a_save_accepted_just_before_it` does not reopen the
   app. The first version did, and it passed even with cancel mode: the
   database worker kept running in the test process and committed later. A real
   quitting process does not live that long. The test now holds the database
   lock for 200 ms, so the save cannot finish at once. Right after the shutdown
   call returns, it reads the committed rows through a second connection. With
   cancel mode in place of graceful mode, this test failed 3 of 3 runs; with
   the fix, it passed 5 of 5.
2. The Mac test calls `MacAppDelegate.quit(reply:)` instead of
   `applicationShouldTerminate`. The tests run inside the app, so a real
   `reply(toApplicationShouldTerminate: true)` would end the test host.
   `applicationShouldTerminate` only returns `.terminateLater` and hands the
   reply to `quit`.
