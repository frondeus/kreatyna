Status

Context

This epic builds the hand-made DAG recipe, the MVP from the accepted recipes brief (D-06). The mockups sections 1–4 show the target. A recipe is a title, a list of ingredient lines (“400 g Mutti tomatoes → tomato”), and steps on a canvas connected into a graph (“Fry onion & garlic” comes after “Dice onion” and “Mince garlic”). The app shows it as stages and gives a one-cook total time (“38 min”).

It assumes the Mac shell epic is done: a Mac window over the Rust core, with the catalog at parity and Counter gone. Recipes are Mac-only for now; iPhone recipe screens are a non-goal.

Goal: on the Mac you can create, read, edit, search and delete recipes. Each has ingredient lines (optionally linked to the catalog) and a canvas of timed, connected steps, and saves only when complete (D-37).

Architecture

Domain and persistence

  • A new recipes module in crates/kreatyna, next to ingredients, with UUID newtype identities for recipes, ingredient lines and steps. Recipe titles use the catalog's name key, so “Shakshuka” and “shakshuka ” collide (D-39).
  • Tables arrive one slice at a time as forward-only migrations: recipes (REC-01), ingredient lines (REC-07, catalog link added in REC-10), step nodes with canvas positions (REC-14), step edges (REC-18) and step uses of lines (REC-20).
  • No drafts (D-40): the editor holds the whole recipe in Rust and saves it in one transaction on Save. Cancel throws the edit away.
  • Amounts reuse the catalog's exact decimals. Units are known (g, kg, ml, l, tsp, tbsp, cup, piece), a linked ingredient's reference unit (“clove”), or custom text kept as written (D-25).

Widgets and navigation

  • Recipe list, read view and editor widgets, composed by a recipe coordinator with typed navigation that mirrors the catalog's: list → read view → editor, and list → editor for a new recipe. Edit replaces the detail pane (D-18).
  • REC-01 introduces Rust-owned app sections (Recipes, Ingredients). The Mac sidebar projects them; iOS keeps showing only Ingredients.
  • The catalog is reached through capabilities: name suggestions (REC-11), reference units (REC-12), and “how many recipes link this ingredient” for the delete confirmation (REC-13).

The graph

  • Pure Rust functions over steps and edges, each arriving with the slice that needs it: the cycle check (REC-18), stages, meaning “what can start together” (REC-19), and the one-cook scheduler (REC-21: active steps never overlap, waiting steps run in the background).
  • The canvas is a SwiftUI view. Rust owns node positions, edges, selection and every rule. Swift owns only the drag in progress, hover, and the rubber-band line while you drag from a port. Dropping sends one event (move, connect); if Rust rejects it, the next render shows the truth.

Suggested order

    Slices

    Each slice is its own jj change and review. Its implementation plan is written in tasks/<ID>.md when the slice starts, not before. Layers show where the slice changes code: db migration and Diesel, rust domain and widgets, ffi UniFFI types and build, swift SwiftUI and its tests.

    Open questions

    Details the brief leaves open. Each has a proposal, settled in the slice's plan with the user.

    Out of scope

    Everything after the MVP stays on the brief's roadmap, to be picked after using the MVP (D-38):

    • Timing and the make-ahead flag, cooking mode and timers, inline tokens and the unit setting, paste/URL import, combining recipes, the iPhone shell and sync.
    • Parked features F-01 … F-13: recipe fields beyond the title, auto-arrange, partial line use, ingredient groups, creating catalog ingredients from a line, duration ranges, personal timings, two cooks, pantry-aware time, “how far ahead”, drafts, and the timeline view.
    • Undo/redo on the canvas, zooming and panning beyond scrolling, keyboard-only canvas editing.
